# Working preferences for this repo

- The user prefers PRs merged automatically once they're ready (tests passing, no open concerns) rather than being asked each time. Merge without waiting for an explicit "merge it" — but still flag anything unusual (failing tests, a risky/destructive change, a conflict) before merging, and hold off merging if something genuinely needs their input first.
- Never use `CookzerModal.prompt()` (or any text-input dialog) for picking one of several options — e.g. "type the number from this list" to choose a recipe, or to pick who's suggesting something. It reads as unprofessional. Build a real picker instead: a search input + a clickable list of rows, and/or a row of selectable chips. See `cookzer-planner.html`'s `#pickerOverlay`/`#pickerModal` (`.cz2-*` classes) for the established pattern — reuse or extend it rather than reintroducing a numbered-list prompt. Plain `CookzerModal.alert()`/`.confirm()` for simple messages or yes/no confirmations are fine and unaffected by this.
- Never trigger a native OS/browser dialog (e.g. `navigator.share()`'s OS share sheet, `window.print()`'s dialog where an in-app alternative makes sense, etc.) — it carries the OS's own chrome and can't be styled or kept in-app, same problem `cookzer-modal.js` exists to solve for alert/confirm/prompt. Use `CookzerModal.share({ title, url, text })` for anything that used to call `navigator.share()` — it shows an in-app popup with the link + a Copy button + quick-share links (WhatsApp/Facebook/X/Email) instead.
- When a chat reply contains something the user needs to do (run a migration, make a decision, review something before it can proceed, etc.), lead that line with a `█` marker so it's easy to spot at a glance. Don't use it for routine status updates or things that don't need action from them.
